# Authentication Experience Polish v2 — Implementation Plan

> Planning only. No code, no commits, no unrelated refactors this sprint. Grounded in the codebase, the "before" screenshot, the approved reference, your 4 decisions, and 9 corrections.

## 0. Starting point
Next.js 16.2 / React 19, TS strict, CSS Modules, Tailwind v4 bridge, hand-rolled CSS motion (no Framer/GSAP), custom `data-theme` light/dark (FOUC-free), Geist Sans, mature token system in `globals.css`.
**Tree:** `LoginPage` (server) → `LoginExperience` (7-phase orchestrator) → `HangingLamp` (sole input controller) + `roomDim`/`ambientLight` + `spotlightZone→logoStage→{logo}` + `cardFrame→borderTrace(SVG)→cardSurface(glass)→stagger`. One-directional bridge (`HangingLamp.phase → onPhaseChange → handleLampPhase`); the experience never commands the lamp.
**Problems:** cone too narrow/centered on card top → card is merely *spotlighted*, not living inside the light; logo reads attached to the card and risks lamp collision; mark is a separate floating check over a 3-piece A (does **not** match the mockup); border is a single trace + faint shimmer, not chasing particles; animations feel like parallel timers, not a causal chain; glow trends neon rather than physical.

## A. BINDING RULES (acceptance criteria — override any conflicting detail)

**R1 — Logo fidelity.** Geometry must visually match the approved mockup. The "A" and integrated checkmark read as one geometric object. Do not reinterpret/redesign proportions. Faithfully reproduce the approved brand mark.
**R2 — Light wraps the card.** The login card must appear to live *inside* the illuminated cone. The cone extends beyond the left and right edges of the card with soft feathered falloff. The card must never appear merely spotlighted from the center.
**R3 — Protected logo zone (no lamp overlap).** Maintain a protected vertical logo zone. The hanging lamp must never overlap the wordmark or tagline at any viewport. Adjust spacing responsively instead of allowing collisions.
**R4 — Cord exits from inside the lamp.** The pull cord emerges through the shade's bottom-center aperture, not beside or in front of the shade.
**R5 — Lamp feels heavy.** The lamp must feel like a suspended architectural pendant weighing several kilograms. Motion exhibits inertia and restrained damping — not playful swinging.
**R6 — Border = residual energy.** The four particles visually feel like residual energy emitted by the lamp, not decorative UI effects. Causally downstream of the light, not an independent ornament.
**R7 — No over-glow.** Avoid cyberpunk/neon aesthetics. Glow stays physically believable, soft, warm, premium. Bounded, never blooming.
**R8 — Visual fidelity over implementation convenience.** Prioritize visual fidelity over implementation convenience. If the rendered result does not visually match the approved reference, the implementation is incomplete even if the code architecture is technically correct. Continuously compare the rendered UI against the approved reference and iterate until the visual composition, spacing, proportions, lighting, logo geometry, and motion closely match the design intent. Do not optimize prematurely. Finish the complete visual experience first. Only after the design matches the approved reference should implementation details, refactoring, or optimization be considered. Success is measured by what the user sees.
**R9 — FINAL ACCEPTANCE CRITERION.** This sprint is complete only when a designer comparing the implementation against the approved reference would be unable to identify meaningful visual differences without intentionally looking for them.

## 1. Hero Experience
Lamp = sole controller & emotional origin; nothing reveals before the light reaches it. Keep the one-directional bridge. Re-anchor downstream phases to the lamp's *emitted* ignition events → causally chained (§10), not parallel timers. Cord = only interactive input.

## 2. Visual Hierarchy
Order (brightest → softest): **Lamp → Logo → Tagline → Card → Controls**, via z-order + luminance. Rule: logo wordmark contrast ≥ card border contrast > tagline contrast > ambient shimmer, with per-layer opacities. Card is translucent glass by design (per R2 it is *immersed* in light). Buttons inherit the card surface. Glow capped per R7 — only the lamp may bloom.

## 3. Logo Placement (R3)
**Protected vertical logo zone** replaces hardcoded `padding-top:340px`/`pullHint top:300px`. Define `--auth-logo-zone` (top+height): lamp's lowest point (shade bottom + cord-knob drop) + guaranteed gap (`--auth-logo-gap-min`) defines zone **top**; wordmark + tagline live inside; card begins only below it. Responsive rule: if a viewport would cause lamp-bottom + logo to collide, **shrink the lamp unit (rod token + cone) first**, never let the logo ride up — no viewport may overlap wordmark/tagline (R3). Seat the logo in the cone's brightest band; soft lit ground-shadow → floats *in* light, not glued to glass. Light reaches the logo (`spotlight`, ~t0.5s) before the card surface (~t2.0s). No visual connector between logo and card.

## 4. Logo Quality (R1, R8)
**Reproduce from the approved mockup, not redesign.** Begin by tracing the approved mark at high fidelity (viewBox 0 0 100 100), locking exact proportions, apex angle, counter shape, and the integrated A+check as **one geometric object** (negative-space check — the check is the *absence* of material inside the A's lower counter, not a separate stroke on top). No reinterpretation, no separate check path layered over. Per R8: iterate the SVG against the reference until visually indistinguishable — no "close enough."
**Wiring:** master `public/brand/mark.svg` = faithful reproduction; `icon.svg`/`icon-192.svg`/`icon-512.svg` regenerated from that exact path (replacing the divergent 3-piece-A and hollow-A — both fail R1); `monogram.svg` aliased/removed; `logo.svg` + `logo-dark.svg` embed the *same* mark path byte-for-byte — only wordmark/tagline colors differ by theme. Eliminates the three conflicting gradients + separate-floating-check in one pass.

## 5. Lamp Construction (R4 + R5)
- **Cord through the shade (R4):** re-anchor `pullCordGroup` so the string emerges from the shade's bottom-center aperture (through the bulb area) and drops to the knob; string top occluded by the shade lip → reads as coming *through* the lamp — not beside/in front (current bug: cord anchored at shade top, passing in front).
- **Architectural weight (R5):** refine `lampShade` to the mockup's short truncated-cone/cylinder — matte metal exterior, warm interior, rigid `lampRod` hanger (correct vs ref) with refined metal gradient + highlight seam. Add an inner aperture glow (warm light spilling down from the shade mouth), distinct from the main cone — sells "light source inside a heavy metal object."
- **Heavy motion (R5):** replace the playful spring `cubic-bezier(0.34,1.56,0.64,1)` and 1.6° swing. Use **heavily-damped motion**: critically/over-damped easing (no overshoot — a multi-kg pendant does not bounce), swing ≤0.8°, slow settle with inertia (long decaying tail). Cord spring-back loses overshoot → damped return. The 6s idle `lamp-float` reduced to near-imperceptible drift (or removed if it reads as a "toy"). Net: reacts to a cord pull like a heavy object on a stiff rod — a slow, weighted sway that stops itself.
- **Decouple geometry:** introduce `--auth-lamp-rod-height` token (+ derived offsets) replacing `ROD_BASE_HEIGHT=188`. Feeds §3 and §15.

## 6. Light Cone (R2, R7)
- **Wrap, not spotlight (R2):** cone base extends **beyond the left and right edges of the card** with soft feathered falloff. Card never appears center-spotlit.
- **Feathered geometry:** replace the hard `clip-path` trapezoid (38%→62%, ~460×760 — the forbidden "spotlight dot") with a layered composite using **gradient masks** for edge falloff: `lightCore` (tight warm-white at bulb) + `lightBloom` (mid warm) + `lightConeInner` (volumetric beam, feathered edges) + `lightConeOuter` (wide, very low-opacity wash extending past card L+R → card reads immersed).
- **Intensity** peaks at the logo band, softens toward/around the card; warm tint on the card's top edge → lit-from-above.
- **Wrap-around cues:** top-lit highlight on the card top edge + soft shadow pooling below = "object inside light."
- **Glow cap (R7):** all layers bounded — warm-white dominant, teal only low-opacity accent; peak opacity capped per layer → physically believable, not blooming.
- Phase-reactive (`igniting` ramp → `ambient` steady); reduced-motion snaps to final.

## 7. Login Card (premium glass)
Spacing aligned to the type scale; typography via `--type-*` (tighten title, relax description, optically align Google button text/icon). Glass: tune `blur(24px) saturate(1.2)` per theme (dark slightly higher blur), add a 1px inner-top lit highlight (ties to R2) + soft inner shadow; **resolve the 4× duplicated glass tokens in globals.css** to one set. Elevation: layered ambient/key/contact shadows (`--shadow-*`, stronger in dark) + subtle top-third sheen. Unify cardFrame/cardSurface/border-SVG/`--glass-radius` to one radius token. Warm-tinted cast shadow under card. Balance: centered content, consistent button widths, lighter divider. **Fix swapped `.errorIcon`/`.successIcon` colors** (~L296/303).

## 8. Brand Typography
Wordmark: keep two-tone, single weight; resolve `font-family="Inter"` vs the app's **Geist Sans** (recommend Geist, baked into the SVG). Letter-spacing tighten on wordmark (~-0.02em), widen on tagline (overline feel). Tagline lower weight/smaller/more spaced/lower opacity → below wordmark in hierarchy. Encode wordmark→tagline gap and the protected-zone gap as tokens. Optically align tagline to the wordmark's optical left edge. Consistent spacing around the • separators.

## 9. Border — four particles as residual energy (R6, R7)
Keep the single-path reveal as *introduction* (one trace draws clockwise at `frame-tracing` — "the light is drawing the glass"), then **hand off** to four particles at `ambient`. The particles are the lamp's residual energy spilling around the perimeter — so they inherit the **same warm→teal palette as the cone**, originate conceptually from the bulb, behave like light caught orbiting the glass — not a spinner or neon tube.
Construction: four short gradient light-segments, each on the same `buildBorderPath` geometry (`pathLength=1000`, `stroke-dasharray ~ "90 910"`), each animated `stroke-dashoffset 0→-1000` linear infinite, each **delayed 1/4 loop** → 90° spacing, chasing forever, never colliding. Soft `drop-shadow` glow for comet softness; blended head/tail. Never a rotating glow or spinning border — segments travel the path; the card never rotates. **Glow cap (R7):** particle peak opacity low, blur soft — energy, not neon. Lifecycle: hidden → `frame-tracing` single draw → `surface/content` trace + faint static frame → `ambient` four chasers take over → reverse: chasers fade then trace un-draws.

## 10. ON Timeline (causal, ~3.6–4.0s, weighted per R5)
Cord pulled (haptic + `switchClick`, t0) → **lamp begins a slow weighted sway** (inertial, damped, ≤0.8° — R5) → bulb ignites + flash (~0.15s) → lamp reports `illuminated` (~0.38s) → **experience chain starts**: cone expands and *wraps* (R2) + **logo fades in/settles** in the protected zone (0.5s, no lamp overlap R3) → border trace draws (1.2s) → glass card materialises/rises + lit top edge + cast shadow, *inside* the cone (2.0s) → contents stagger ~85ms each (2.4s) → trace hands off to the four energy particles + logo idle glow (3.2s). Each step gated on the previous step's visible progress.

## 11. OFF Sequence (fully reversible)
Cord pulled again (t0) → four particles fade (energy dissipates) → card surface fades+sinks (border ghost remains briefly) → logo dims → border un-draws → cone contracts/dims → lamp dark → room dark. `clearTimers()` at the start of both forward/reverse prevents overlap; a mid-sequence pull cleanly cancels and re-targets.

## 12. Motion Language (unified tokens, full migration; serves R5)
Add to `globals.css :root`: easings — `--motion-ease-expo-out: cubic-bezier(0.16,1,0.3,1)` (promote the curve used ~12×), `--motion-ease-damped: cubic-bezier(0.22,1,0.36,1)` (over-damped, **no overshoot** — heavy lamp per R5); replace the bouncy `--motion-ease-spring`. Durations — `--auth-duration-flash 460ms`, `-ignite 380ms`, `-reveal 600ms`, `-trace 1400ms`, `-cone 1000ms`, `-shimmer 18s`, `--auth-stagger 85ms`, plus long `--auth-duration-settle` for the weighted sway. Timeline anchors — `--auth-t-spotlight 500ms`, `-frame 1200ms`, `-surface 2000ms`, `-content 2400ms`, `-ambient 3200ms`. Migrate every inline curve/`ms` in the 3 auth CSS modules (1:1 except where R5 removes overshoot). Preserve comprehensive reduced-motion overrides.

## 13–14. Themes
**Light:** keep teal-tinted canvas (`#edf4f4`/`#dce8e9`), avoid flat white; verify `--auth-veil-strength:0.32` makes lit/unlit delta readable; glass card slightly *darker* than canvas for depth; bump `lightCore`/`lightBloom` opacity so "lamp on" is believable on light bg (within R7's cap); glass not washed out + inner-top lit edge.
**Dark:** canvas (`#0d1422`/`#090d18`) + 0.86 veil = premium stage; keep. **Luxurious, not cyberpunk (R7):** cap teal saturation — `lightConeOuter` teal low opacity, glows warm-white-dominant, no pure-neon strokes. Border particles soft + low peak opacity. Glass: higher blur + stronger shadows; keep AAA contrast. Verify dark wordmark (`#ECEEF3`/`#2DD4BF`/tagline `#94A3B8`) reads inside the wrapped cone.

## 15. Responsive (R3 across viewports)
Scale lamp + cone as a unit via `--auth-lamp-rod-height` and `--auth-logo-zone`; rest reflows. **Collision rule (R3): on any viewport where the lamp would approach the wordmark/tagline, shrink the lamp unit first — never allow overlap.** Desktop ≥64rem: full rod/cone, generous logo band. Tablet 48–64rem & landscape: rod ~-15%, cone narrows but still extends past card L+R (R2 holds), card `min(100%,26rem)`, wordmark ~240px. Mobile ≤30rem: rod ~70%, cone follows card width (still wraps per R2), logo band compressed but protected, larger cord-knob hit area, pull-hint via token. Short laptops (≤820/≤720px): `padding-top` derived from `--auth-logo-zone`; `justify-content:flex-start` on very short screens (keep). Touch: Pointer Events cover mouse+touch; haptics retained where supported.

## 16. Accessibility (preserve + extend)
Keyboard: cord `role=button` + `tabIndex 0` + Enter/Space (keep); logical focus order; visible `:focus-visible` (keep). Reduced motion: every new animation gets a fallback; **no infinite ambient motion under reduced-motion** (the four particles and idle sway must stop). Screen readers: card `role=region aria-labelledby=login-title` (keep); cord `aria-pressed` (keep); **add `aria-live=polite` state announcement** ("Lampu menyala"/"Lampu padam"); decorative layers stay `aria-hidden`. Focus: don't auto-focus on load. High contrast: **add `@media (forced-colors:active)` fallback** (solid borders instead of glass/blur). Color-only: login controls always operable regardless of visual phase.

## Implementation Phases (execution only — not now)
**Per R8: visual fidelity is chased first and verified by direct side-by-side comparison against the approved reference at each phase. Optimization, refactoring, and code-elegance work are explicitly deferred until after the rendered experience visually matches the reference. "Done" for each phase = the rendered result matches the reference, not "the code is correct."**

- **P1 The mark (gating, R1/R8):** **trace the approved mockup** into `mark.svg`; iterate until visually indistinguishable; regenerate icon/monogram/PWA icons from that exact path; re-embed in logo/logo-dark; update `<Logo>` + `layout.tsx`; fix typography font.
- **P2 Lamp & cone (R2/R4/R5/R8):** re-anchor cord through shade center; refine shade + aperture glow; weighted damped motion; widen + feather cone to extend past card L+R; couple offsets to rod token. Iterate look + cone against reference.
- **P3 Logo placement (R3/R8):** build protected `--auth-logo-zone`; reflow spotlightZone/logoStage (independent, centered in bright band, no lamp overlap at any viewport); lit ground-shadow; tune tagline/wordmark contrast + spacing.
- **P4 Card polish (R8):** spacing/glass/elevation/radius/shadow unification; warm cast shadow; fix swapped icon-color bug.
- **P5 Four-particle border (R6/R7/R8):** chase system on existing path, palette tied to the cone; trace→particles handoff at ambient; reverse fade; capped glow.
- **P6 Timeline & motion language (R5/R8):** re-anchor forward/reverse to causal timings with weighted lamp motion; verify ON/OFF = one chain; match motion feel to reference.
- **P7 Foundation tokens (R8-deferred):** *only after* visual match — consolidate 4× glass tokens, migrate inline easings/durations to the §12 tokens (1:1), tokenize `--auth-lamp-rod-height` + `--auth-logo-zone` for maintainability.
- **P8 Theme + responsive + a11y pass (R3/R7):** §13/14 tuning; §15 protected-zone responsive scaling + glow-cap enforcement; `aria-live` announcements, forced-colors fallback, reduced-motion for all new animations. Re-verify fidelity on every breakpoint.
- **P9 Visual Review Loop (MANDATORY before completion):** Implementation is not complete after the code compiles successfully. At the end of **every** implementation phase, compare the rendered UI side-by-side with the approved concept. Review these dimensions individually: (1) Logo geometry (2) Logo placement (3) Lamp proportions (4) Lamp realism (5) Cord realism (6) Light cone composition (7) Card composition (8) Motion quality (9) Border animation (10) Typography (11) Visual balance (12) White space (13) Depth (14) Premium perception. If any area still differs noticeably from the approved concept, return to the responsible implementation phase and iterate again. Do not continue because "it is technically correct." Continue because **"the rendered experience feels identical."**

## Risk Assessment
- **Mark fidelity in one pass** (Med/High) → trace the mockup; gating asset; iterate per R8/P9 until indistinguishable.
- **Rendered drift mid-build** (Med/High) → R8 + P9: side-by-side at the end of *every* phase; re-enter if it drifts.
- **Feathered cone perf on low-end** (Low-Med/Med) → layered radial gradients over SVG filters; cap blurs; throttled-CPU test — only after visual match (R8).
- **Particles read as dashes/neon** (Med/Med) → tune `90/910` dash + soft `drop-shadow` + gradient head/tail + warm→teal palette; low peak opacity (R6/R7); iterate via P9.
- **Protected-zone collision on some viewport** (Med/High) → `--auth-logo-zone` single primitive; "shrink lamp first, never overlap" at every breakpoint (R3).
- **Lamp reads too lively after damping** (Low/High) → over-damp aggressively, ≤0.8°, long settle tail.
- **Over-glow creeping back** (Med/High) → R7 as a hard per-layer opacity cap; P9 screens for neon/bloom.
- **Premature optimization stealing time from visual work** (Med/High) → R8: P7 deferred until after visual match; resist cleaning up during P1–P6.
- **Reduced-motion regressions** (Low/High) → write the reduced-motion block *first* for each new animation.
- **Designer still finds meaningful differences at the end** (Med/High) → re-enter P9 with the specific failing dimension(s); do not declare complete until R9 holds.
